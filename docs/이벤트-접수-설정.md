# 이벤트 참여 내용 받아 보기 (Google 스프레드시트 + 드라이브)

참여 페이지(`join.html`)에서 누군가 제출하면 **모든 내용이 운영자 본인의 Google 스프레드시트 한 개**에 모입니다.
따로 서버를 빌리거나 관리할 필요가 없고, 비용도 없습니다. 처음 설정은 10분쯤 걸리고 한 번만 하면 됩니다.

> **중요: 이 설정을 마치기 전에는 참여 페이지의 제출 버튼이 "접수 준비 중"으로 막혀 있어 아무도 참여할 수 없습니다.**

## 어디에 무엇이 모이나요?

스프레드시트 하나에 탭 세 개, 드라이브에 폴더 하나가 생깁니다.

| 위치 | 들어 있는 것 | 쓰는 곳 |
|---|---|---|
| 시트 `접수` | 한 사람당 한 줄: 접수번호, 시각, **이름, 이메일, 휴대폰**, 설문 12문항 답, 자유 의견, 동의 여부, 리포트 링크 | 추첨, 당첨 연락, 중복 확인 (개인정보 원본이라 **운영자만**) |
| 시트 `집계` | 문항별 응답 수·비율, 5점 문항의 **긍정 응답률·평균**, 1인 평균 거래액 추정 | **사업계획서에 넣을 수치.** 새 접수가 들어오면 자동으로 다시 계산됨 |
| 시트 `통계용` | 이름·이메일·휴대폰·리포트 링크를 **뺀** 설문 응답만 | 팀원에게 보여 주기, 엑셀로 내려받아 직접 분석하기 |
| 드라이브 `COMFIT 이벤트 리포트` 폴더 | 참여자가 첨부한 검진 리포트 파일 | 시트의 "리포트 링크"를 누르면 열림 |
| (켜 두면) 내 Gmail | 접수될 때마다 알림 메일 | 실시간 확인 |

한 번에 보려면 **스프레드시트를 즐겨찾기**해 두세요. 휴대폰의 Google Sheets 앱으로도 볼 수 있습니다.

---

## 1. 스프레드시트 만들기

1. 운영용 Google 계정으로 <https://sheets.new> 를 엽니다.
2. 왼쪽 위 제목을 `COMFIT 이벤트 접수`로 바꿉니다.

## 2. 접수 코드 붙여 넣기

1. 스프레드시트 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 처음 보이는 `Code.gs`의 내용을 **전부 지우고**, 이 저장소의 [`tools/apps-script/Code.gs`](../tools/apps-script/Code.gs) 내용을 통째로 붙여 넣습니다.
   (GitHub에서 파일을 연 뒤 오른쪽 위 복사 버튼을 누르면 전체가 복사됩니다.)
3. 저장(디스크 아이콘 또는 `Ctrl+S`)합니다.
4. 위쪽 함수 목록에서 `setup`을 고르고 **실행**을 누릅니다.
   - "승인 필요" 창이 뜨면 **권한 검토 → 내 계정 선택**을 누릅니다.
   - "Google에서 확인하지 않은 앱" 화면이 나오면 **고급 → (안전하지 않음)으로 이동**을 누른 뒤 **허용**을 누릅니다.
     직접 만든 스크립트라 이 화면이 뜨는 것이 정상입니다.
   - 아래 실행 로그에 `준비 완료`가 나오면 성공입니다. 스프레드시트에 `접수`·`집계`·`통계용` 시트가 생기고 드라이브에 폴더가 생깁니다.
   - 예전 양식으로 `setup`을 실행한 적이 있다면, 예전 `접수` 시트는 지워지지 않고 `접수(이전 양식 …)`으로 이름만 바뀝니다.

## 3. 웹 앱으로 배포하기

1. 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 톱니바퀴(유형 선택)에서 **웹 앱**을 고릅니다.
3. 이렇게 맞춥니다.
   - 설명: `COMFIT 이벤트 접수`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** ← 로그인 없이 참여할 수 있게 하려면 꼭 이 값이어야 합니다
4. **배포**를 누르고, 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.

> "모든 사용자"는 *이 주소로 접수를 보낼 수 있다*는 뜻입니다. 시트와 드라이브 파일은 여전히 나만 볼 수 있습니다.

## 4. 사이트에 주소 넣기

1. GitHub 저장소에서 `web/config.js`를 엽니다 → 연필(✏️) 아이콘.
2. 이 줄의 따옴표 안에 복사한 주소를 붙여 넣습니다.
   ```js
   formEndpoint: 'https://script.google.com/macros/s/여기에-받은-주소/exec',
   ```
3. **Commit changes**를 누르면 2~3분 뒤 사이트에 반영됩니다 (Actions 탭에서 진행 상황 확인).

## 5. 시험해 보기

1. 사이트의 `join.html`에서 내 이메일로 한 번 제출해 봅니다 (아무 PDF나 JSON 파일 첨부).
2. "참여가 완료되었습니다"와 접수번호가 보이고, 스프레드시트에 한 줄이 생기면 끝.
3. 시험한 줄은 스프레드시트에서 지워도 됩니다. 같은 이메일로 다시 시험하려면 그 줄을 지우세요(1인 1회 제한).

## 운영하면서

| 하고 싶은 것 | 방법 |
|---|---|
| 참여 목록 보기 | 스프레드시트의 `접수` 시트. 필터·정렬을 마음대로 쓰세요 |
| 사업계획서 수치 보기 | `집계` 시트. "▶ 긍정 응답률"이 핵심 수치입니다 (아래 "사업계획서에 쓰는 법") |
| 설문 원자료 내려받기 | `통계용` 시트를 연 상태에서 **파일 → 다운로드 → Microsoft Excel 또는 CSV(현재 시트)**. 개인정보가 들어 있지 않습니다 |
| 리포트 열기 | 시트의 "리포트 링크" 칸을 누르면 드라이브에서 열립니다 (나만 열림) |
| 추첨 | 빈 칸에 `=INDEX('접수'!A2:A, RANDBETWEEN(1, COUNTA('접수'!A2:A)))`로 접수번호를 뽑고, 그 줄의 이름·이메일·휴대폰으로 연락. 뽑을 때 화면을 녹화해 두면 공정성 확인에 좋습니다 |
| 설문 문항 바꾸기 | `web/join.html`과 `Code.gs`의 `QUESTIONS`를 **글자까지 똑같이** 바꾼 뒤 `setup`을 다시 실행하고 새 버전으로 다시 배포. 접수가 시작된 뒤에는 바꾸지 않는 것이 좋습니다 (앞뒤 응답을 비교할 수 없게 됨) |
| 접수 마감 | `web/config.js`에서 `eventOpen: false` (화면 막기) **그리고** Apps Script `SETTINGS.OPEN = false` 후 다시 배포 (서버도 막기) |
| 알림 메일 끄기 | Apps Script `SETTINGS.NOTIFY = false` 후 다시 배포 |
| 파일 크기 한도 바꾸기 | Apps Script `MAX_FILE_MB`와 `web/config.js`의 `maxFileMB`를 같은 값으로 |
| 개인정보 파기 | 보유 기간이 끝나면 먼저 `집계` 시트와 `통계용` 시트를 **값으로 복사해 새 파일로 저장**(파일 → 사본 만들기 후 `접수` 시트 삭제)해 두고, 원본 스프레드시트와 드라이브 폴더를 지운 뒤 **휴지통도 비우세요**. 개인을 알아볼 수 없는 통계는 계속 보관해도 됩니다 |

### Apps Script 코드를 고친 뒤 다시 배포하는 법 (주소 유지)

**배포 → 배포 관리 → 연필(수정) → 버전: 새 버전 → 배포**. 이렇게 하면 웹 앱 주소가 바뀌지 않습니다.
"새 배포"를 다시 누르면 주소가 바뀌니, 그때는 `config.js`의 주소도 바꿔야 합니다.

### 이미 넣어 둔 보호 장치

- 숨은 칸(봇 덫): 자동 프로그램이 채우면 저장하지 않음
- 이메일·휴대폰 번호당 1회, 1시간 최대 300건 (스팸이 몰릴 때 막는 장치)
- 필수 동의 4가지(약관, 개인정보, 통계 활용, 만 14세·본인 리포트)가 없으면 저장하지 않음
- 허용한 파일 형식만 받고, 확장자와 내용이 다르면 거부 (예: `.pdf`로 이름만 바꾼 실행 파일)
- 시트에 `=`, `+`, `-`, `@`로 시작하는 글은 수식이 아닌 글자로 저장 (수식 주입 방지)
- 설문 답은 정해진 보기만 저장

### 주의

- 첨부 파일은 모르는 사람이 올린 파일입니다. **zip을 풀거나 html을 내 PC에서 열 때 조심하세요.** 드라이브 미리보기로 보는 것이 가장 안전합니다.
- Gmail 무료 계정의 알림 메일은 하루 100통까지입니다. 넘으면 메일만 안 오고 접수는 정상입니다.
- 스프레드시트·폴더를 다른 사람과 공유하지 마세요. 공유하면 참여자 개인정보가 함께 공유됩니다.

## 사업계획서에 쓰는 법

`집계` 시트의 수치를 이렇게 옮기면 됩니다.

| 사업계획서 항목 | 쓰는 문항 | 예시 문장 |
|---|---|---|
| 조사 개요 | 전체 응답자 수, 조사 기간 | "PC 건강검진 DAY 이벤트 참여자 N명 대상 온라인 설문 (2026. 11. 20.~11. 30.)" |
| 시장 참여율 | Q1 | "응답자의 OO%가 최근 1년 안에 중고 PC·부품을 거래" |
| 시장 규모 근거 | Q2 (1인 평균 거래액 추정) | "1인당 연간 중고 PC·부품 거래액 약 OO만 원 (구간 응답의 가운데 값으로 추정)" |
| 문제 확인 | Q3, Q4, Q5 | "OO%가 거래 중 어려움 경험, 가장 큰 어려움은 '부품 상태 확인'(OO%)" |
| 해결책 수요 | Q6, Q7 | "객관 지표 기반 중개 사이트 필요 OO%, 이용 의향 OO%" |
| 가격 프리미엄 | Q8 | "OO%가 검증 매물에 시세보다 3% 이상 더 낼 의향" |
| 제품 만족도 | Q9, Q12 | "검진 만족 OO% (5점 만점 평균 O.O점), 추천 의향 OO%" |
| 수익 모델 | Q10 | "리포트 유료화(1,000~3,000원) 시 지불 의사 OO%" |
| 기능 우선순위 | Q11 | "가장 원하는 서비스 1위 OO(OO%)" |
| 잠재 고객 | 소식 수신 동의 수 | "출시 알림을 받겠다고 동의한 잠재 고객 OO명" |

주의할 점
- "긍정 응답률"은 *매우 그렇다 + 그렇다* 비율입니다. 사업계획서에는 이 기준을 한 줄 적어 두세요.
- 응답자는 경품 이벤트에 참여하고 이미 검진을 한 사람들이라, 실제보다 관심이 높게 나올 수 있습니다.
  조사 대상과 기간을 꼭 함께 적고, 가능하면 "이벤트 참여자 대상"이라고 밝혀 두는 것이 심사에서 더 믿을 만하게 보입니다.
- 응답자가 적으면 수치가 크게 흔들립니다. 대략 100명이면 ±10%p, 200명이면 ±7%p 정도의 오차가 있다고 보면 됩니다.
