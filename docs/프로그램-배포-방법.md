# 검진 프로그램 새 버전 올리기 (GitHub Releases)

새 버전을 이 저장소(`comfit_web_2026`)의 **Releases**에 공개하면, 다운로드 페이지가 2~3분 뒤 자동으로 바뀝니다.
`web/config.js`를 고칠 필요가 없습니다.

자동으로 바뀌는 것: 다운로드 버튼 주소, 버전, 출시일, 파일 크기, SHA-256 확인 값, "이 버전의 변경 내역" 버튼

> 프로그램 소스 코드(`comfit3`)는 비공개 저장소라서 방문자가 그쪽 파일을 받을 수 없습니다.
> 그래서 설치 파일은 공개 저장소인 이곳에 올립니다. 소스 코드는 올리지 않습니다.

## 새 버전 올리는 순서

1. GitHub에서 이 저장소 → 오른쪽 **Releases** → **Draft a new release**
2. **Choose a tag**에 버전을 적고 **Create new tag** (예: `v0.1.0`). 이 글자가 그대로 사이트의 "버전"에 나옵니다.
3. **Release title**: 예 `COMFIT v0.1.0`
4. 설명란에 바뀐 점을 적습니다. ("이 버전의 변경 내역" 버튼이 이 페이지로 연결됩니다)
5. 아래 상자에 **설치 파일**(`.exe`)을 끌어다 놓습니다.
6. **Set as a pre-release**: 정식 배포 전 베타면 체크합니다. `config.js`의 `includePrerelease: true`(지금 값)면 베타도 사이트에 나오고 "베타" 표시가 붙습니다.
   정식 버전은 체크하지 않습니다.
7. **Publish release**

진행 상황은 **Actions** 탭의 "사이트 배포"에서 볼 수 있습니다.

## 알아 둘 것

| 상황 | 결과 |
|---|---|
| 릴리스를 공개·수정·삭제함 | 사이트가 다시 배포되어 그 시점의 **최신 릴리스**를 보여 줌 |
| 초안(Draft)으로 저장 | 사이트에 나오지 않음 |
| pre-release(베타)로 공개 | `includePrerelease: true`면 다운로드에 나오고 "베타" 표시와 안내가 붙음. `false`면 나오지 않음 |
| 정식 버전을 공개한 뒤 | 정식이 더 최근이면 정식이 나옴. 베타를 다시 보이지 않게 하려면 `includePrerelease: false` |
| 문제가 있는 버전을 내리고 싶음 | 그 릴리스를 삭제하거나 초안(Draft)으로 되돌리면 이전 버전이 다시 최신으로 표시됨 |
| 릴리스에 파일이 여러 개 | `.exe` → `.msi` → `.msix` → `.zip` 순서로 하나를 고름. 특정 파일을 고르려면 `config.js`의 `releaseAsset`에 파일 이름의 일부를 적음 (예: `'Setup'`) |
| 릴리스가 하나도 없음 | `config.js`에 직접 적은 값을 씀 (비어 있으면 "다운로드 준비 중") |
| 자동 기능을 끄고 직접 적고 싶음 | `config.js`의 `autoRelease: false` 후 `downloadUrl` 등을 직접 적음 |

- SHA-256 값은 GitHub가 파일을 받을 때 계산한 값을 씁니다. 방문자는 받은 파일이 바뀌지 않았는지 이 값으로 확인할 수 있습니다.
- 출시일은 릴리스를 공개한 날(한국 시간)입니다.
- 나중에 프로그램 저장소(`comfit3`)의 Actions가 릴리스를 자동으로 만들게 하려면, 그 Actions가 **개인 토큰(PAT)** 으로 이 저장소에 릴리스를 만들어야 합니다.
  기본 `GITHUB_TOKEN`으로 만든 릴리스는 사이트 배포를 다시 실행하지 않습니다 (GitHub의 규칙). 이 경우 Actions 탭에서 "사이트 배포"를 직접 실행(Run workflow)하면 됩니다.

## 정식 배포 전 베타 내보내기 (comfit3)

1. `comfit3` 저장소 Actions의 `build` 작업(성공한 것) → 결과물 `comfit-release`를 받아 압축을 풉니다.
   `COMFIT-Setup-<버전>.exe`, `COMFIT-<버전>-win-x64-portable.zip`, `SHA256SUMS.txt`가 들어 있습니다.
2. 이 저장소에서 새 릴리스: 태그 예 `v1.0.0-beta.1`, **Set as a pre-release 체크**, 위 세 파일을 올리고 설명란에 `SHA256SUMS.txt` 내용을 붙입니다.
3. 사이트는 설치 파일(`.exe`)을 다운로드 버튼에 걸고 "베타" 표시를 붙입니다.
4. 정식 버전은 `comfit3`의 `main` 위 `v*` 태그 빌드(운영 키 포함) 결과물을 같은 방법으로, pre-release 체크 없이 올립니다.
